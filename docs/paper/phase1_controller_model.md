# Phase 1 controller model: information, policies, and objective

**Status:** formalization draft v0.3; requirements 1–2 of `conference_roadmap.md`.
**Branch:** `feat/research-censored-feedback`.
**Scope:** definitions and comparison criterion only. No lower bound or novelty claim is asserted here.

This document fixes the control problem to be analyzed in Phase 1. It uses
the canonical router, admission, and gauge definitions in
`docs/formal_definitions/formal.md` and `docs/paper/formal_core.md`.

## 1. Plant and timing

Fix integers `E`, `K`, and `T`, where `1 <= K <= E`. The first Phase 1
model has a fixed, known capacity vector `C in N_0^E` and fixed, known
target `mu in Delta^(E-1)`. Each round `t = 0,...,H-1` receives an
exogenous affinity matrix `a_t in R^(T x E)`. The affinity sequence is
oblivious: it is fixed before the controller acts, but its future entries
are not revealed to either controller. To exclude unbounded score-margin
effects, the environment class may impose a common bound
`max_{t,i,e,e'} |a_{t,i,e} - a_{t,i,e'}| <= M`.

The pressure state satisfies

```text
q_t in Q = {q in R_+^E : min_e q_e = 0}.
```

Both information regimes start from the same fixed, declared initial
state `q_0 in Q`; it is part of the problem instance and may not depend on
the environment or controller's private randomness.

At the start of round `t`, the router uses the current state and the
current affinity matrix:

```text
s_{t,i,e} = a_{t,i,e} - gamma q_{t,e}
I_{t,i} = TopK_K(s_{t,i,:})
R_{t,e} = sum_i 1{e in I_{t,i}}
A_{t,e} = min(R_{t,e}, C_e)
J_{t,e} = R_{t,e} - A_{t,e} = [R_{t,e} - C_e]_+.
```

The fixed tie-breaking rule is shared by both information regimes.
Consequently, `sum_e R_{t,e} = KT` and `sum_e A_{t,e} + sum_e J_{t,e} = KT`.

After the batch has been routed and admitted, the controller receives its
round-`t` observation and selects a feedback vector `epsilon_t`. Both
regimes then use the same pressure dynamics:

```text
q_{t+1} = Pi_g((1-delta) q_t + eta gamma epsilon_t),
```

Here `Pi_g(z) = z - (min_e z_e) 1` is the canonical gauge map. This
matches the implemented dynamics and `formal_core.md`: `gamma` scales
pressure in the router scores and also scales the feedback update. The
coordinate-form update in `formal.md` currently omits this `gamma`; this
draft follows the implementation convention pending a separate
correction to that inconsistent formula.

The shared parameters satisfy `eta > 0`, `gamma > 0`, and `delta in
[0,1)`. The controller cannot change the already-realized routing or
admission in round `t`; its update can affect round `t+1` onward.

## 2. Information regimes and causal policy classes

The common information available after round `t` is

```text
z_t = (q_t, E, K, T, C, mu, eta, gamma, delta, nu,
       epsilon_0,...,epsilon_{t-1}).
```

The controllers do not observe the affinity matrices, token-level scores,
or future affinity matrices. They may retain arbitrary internal memory
derived from their allowed observations and actions. The only difference
between regimes is the per-round load statistic:

```text
Requested observation:  o^R_t = R_t.
Admitted observation:   o^A_t = A_t.
```

The admitted regime knows `C`, so it also knows the saturation pattern
`S_t = {e : A_{t,e} = C_e}`. It does not observe `R_t` or `J_t`. Under
canonical admission, `A_t` and `C` reveal `R_{t,e}` exactly when
`A_{t,e} < C_e`; on saturated coordinates they reveal only
`R_{t,e} >= C_e`. This is the observation model; it is not a claim that
standard routers lack access to `R_t`.

For `X in {R,A}`, let `H^X_t` be the sigma-field generated by the common
information and `o^X_0,...,o^X_t` (and the controller's private random
coins, if randomized). An admissible `X`-policy is a possibly randomized,
non-anticipating map from `H^X_t` to `epsilon_t`. It may use the complete
allowed history, not only the current count vector. To keep the policy
comparison well-posed, both classes use the same admissible update set

```text
U_B = {epsilon in 1^perp : ||epsilon||_2 <= B},
```

for a fixed `B`, or an explicitly stated alternative bound that applies
identically to both classes. Results should state their dependence on
`B`; it must not be tuned to manufacture a gap. Since `Pi_g` removes
common-mode feedback, restricting the update to `1^perp` selects a
canonical representative of the same gauge-equivalence class.

Write `Pi_R(B)` and `Pi_A(B)` for these policy classes. They share the
same initial state, plant, environment class, controller memory allowance,
update bound, and pressure dynamics. No policy has lookahead into future
affinities. Randomized policies are included; paired-environment proofs
must couple the same controller coins when their allowed histories agree.

## 3. Primary cost and comparator

The primary trajectory cost is normalized cumulative token overflow:

```text
O_H(pi; omega) = (1 / (H K T)) sum_{t=0}^{H-1} ||J_t||_1,
```

where `omega = (a_0,...,a_{H-1})` is an affinity sequence in the declared
environment class and all other parameters are fixed. The cost is in
`[0,1]`. This objective evaluates the effect of the controller's pressure
trajectory on future admitted mass; it does not claim that the current
round's scalar overflow is hidden from the admitted controller.

For a randomized policy, write `O_H(pi; omega, xi)` for the realized
cost under private coins `xi`, and define its conditional expected cost
`bar_O_H(pi; omega) = E_xi[O_H(pi; omega, xi)]`.

Let `nu` be a declared probability distribution over the fixed,
oblivious affinity sequences in `Omega_M`. The same `nu` is used for
both information regimes; each controller knows `nu` but not the
realized affinity sequence. Define the shared-environment values

```text
V_X(H; nu) = inf_{pi in Pi_X(B)} E_{omega~nu}[bar_O_H(pi; omega)],
             X in {R,A},
Delta_H(nu) = V_A(H; nu) - V_R(H; nu),
```

where `xi` denotes the policy's private random coins. Policies are
causal maps defined before the affinity sequence is drawn; they may use
their allowed observations as they arrive but cannot depend on future
affinities. The draw from `nu` is independent of each policy's private
coins. For a paired-world lower bound, `nu` may be supported on the
constructed pair of sequences (for example, equal probability on each).

`Delta_H(nu) >= 0` because every admitted policy can be implemented by
a requested-observation policy that ignores `R`. This is the value of
the richer feedback under one shared environment distribution, with the
same initial state, plant, dynamics, and action limits. It does not claim
that the R-policy beats the A-policy on every individual sequence. In a
paired-world proof, the positive expected gap must come from the
R-policy distinguishing the worlds through causal observations while
the A-policy has identical observation histories. Neither policy may
encode or observe future affinities.

The shared-distribution result yields a precise worst-case paired-policy
statement. Let `pi_A^nu` and `pi_R^nu` be `epsilon`-optimal policies for
their respective values under the same `nu`, with `epsilon >= 0`. Then

```text
sup_{omega in supp(nu)}
  [bar_O_H(pi_A^nu; omega) - bar_O_H(pi_R^nu; omega)]
  >= Delta_H(nu) - epsilon.
```

Indeed, the expected cost difference under `nu` is at least
`V_A(H;nu) - (V_R(H;nu) + epsilon)`, and a supremum is at least its
average. The policies are fixed causal maps, and each bracket compares
them on the same affinity sequence. This is a worst-case paired-policy
advantage obtained from a hard distribution. It is distinct from the
robust minimax value difference formed by taking a separate worst case
inside each policy-class value; the hard-distribution argument does not
by itself establish that robust minimax difference.

Requested-target mismatch is a separate secondary metric:

```text
D_H(pi; omega) = (1 / H) sum_t (1/2) ||R_t/(K T) - mu||_1.
```

No arbitrary weighted sum of overflow and target mismatch is used. Any
theorem about `D_H` is a separate result with its own comparator.

## 4. Important identity for the lower-bound design

For every round, mass conservation gives

```text
||J_t||_1 = sum_e J_{t,e} = K T - sum_e A_{t,e}.
```

Therefore the **scalar overflow incurred in the current batch is exactly
observable from `A_t`**. What is censored is the *expert-wise allocation*
of the rejected mass, and that allocation can affect which pressure update
helps future batches. A lower bound cannot be phrased as “the admitted
controller cannot observe its current total-overflow cost.” It must show
that indistinguishable admitted histories conceal a routing-relevant
excess allocation and that the resulting common causal action causes a
positive future cumulative-overflow gap under realizable Top-K affinities.

The secondary mismatch `D_H` is not determined by `A_t` in general, but a
gap in mismatch alone does not establish a gap in the primary overflow
objective. The two claims must remain distinct.

## 5. Requirements for the next theorem

Any paired-environment lower bound must satisfy all of the following:

1. Both environments use valid affinity matrices and the fixed tie rule;
   the induced request counts must be realizable by the stated Top-K
   router at every visited pressure state.
2. The same admitted policy, with coupled random coins, receives identical
   `A` histories and therefore takes the same actions in both worlds.
3. The requested policies distinguish the worlds using `R` without
   future-affinity lookahead.
4. The bound is on `O_H` (or is explicitly labeled as a secondary
   `D_H`/feedback-estimation bound); it quantifies the cost consequence
   over a nontrivial horizon.
5. The result states the roles of `K`, `C`, `mu`, the gauge projection,
   and pressure-state evolution. If those ingredients do not affect the
   bound beyond relabeling a generic censored-demand argument, the
   reduction attack in the roadmap has not been survived.

## 6. Deliberate scope and unresolved extension

This first model fixes `C` and `mu` and assumes one capacity-admission
step after hard Top-K selection. Time-varying capacities/targets, noisy or
delayed counters, local versus global aggregation, and alternative
admission policies are excluded until the base result is established.
The affinity bound `M`, update bound `B`, horizon `H`, and distribution
`nu` (including its support and probabilities) must be fixed before the
lower-bound proof is written. These choices are mathematical assumptions,
not implementation details. The theorem must also justify why the
chosen `nu` captures the intended restricted-telemetry question rather
than a pathological construction. The shared-distribution value gap and
the resulting worst-case paired-policy advantage are now both defined;
the theorem must state which one it proves. Neither implies a positive
difference between the two separately defined robust minimax values.
